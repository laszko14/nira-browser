# Zavro Clean V3 — jedna praca, sześć faz
To wewnętrzna procedura `workflow_mode=autonomous_task`, nie sześć komunikatów użytkownika.
1. **Stan:** rozpoznaj tryb, zakres, produkt, branch i pełny HEAD. Wykonaj G1 według `docs/ai/STARTUP_PREFLIGHT.md`: AGENTS/handoff z tego samego ref, niezbędne dokumenty według zakresu, błędy oznacz `PREFLIGHT_BLOCKED`. Lokalnie opcjonalny `node scripts/ai-preflight.cjs` pomaga dowieść tożsamości checkoutu, nie faktycznych odczytów modelu. Ustal właściciela zapisu; lokalny status ≠ zdalny ref. Nie zakładaj main.
2. **Diagnoza:** obserwowalna akceptacja w TASK_TEMPLATE, minimalny kontrprzykład i przyczyna; analizuj zależności, API, dane i ryzyka. Nie odczytuj całego archiwum, jeśli niepotrzebne.
3. **Zmiana:** izolowany checkout i najmniejsza pełna poprawka. RED/GREEN według TEST_POLICY. Zachowuj profile, certyfikat, dane i stan. Używaj bash (nie fish); żadnych automatycznych stash/reset.
4. **Triage:** po FAIL odczytaj konkretny workflow/run/attempt/job/krok/log, rozróżnij kod/test/konfigurację/infrastrukturę/uprawnienia/zależność, sprawdź fingerprint w ERROR_CASES, napraw przyczynę i uruchom testy dotknięte. Infrastrukturę można selektywnie ponowić po potwierdzeniu; błąd kodu/testu wymaga nowego SHA. Dwie identyczne porażki bez nowych danych → zmień metodę. Nie osłabiaj asercji.
5. **Review:** samodzielna kontrola diffu i wymagane odrębne review w obszarach wysokiego ryzyka, jeśli dostępne; brak recenzenta jawnie BLOCKED dla pełnej oceny ryzyka. Przy implementacji doc-only nie uruchamiaj APK.
6. **Dostarczenie:** zapisz handoff przed pushem; commit/push na uprawnionej gałęzi, zweryfikuj pełny końcowy SHA i wymagane SOURCE oraz PR CI na tym SHA. Każdy wymagany FAIL wraca do diagnozy i poprawki w tym samym zadaniu; nie zaczynaj następnego etapu. Skipped/missing/cancelled nie są PASS. Historyczny FAIL starego SHA nie blokuje poprawnego nowego SHA. Gdy kontrola jest realnie zablokowana, zapisz dowód, powód i brakującą czynność; raportuj BLOCKED/CI_PENDING, bez CODE_VERIFIED. Aktualizuj checkpoint i raport. APK tylko jeśli jawnie żądane przez użytkownika i według osobnego kanonu. Krótki status i STOP.
Preferuj zwykły ChatGPT + bezpośredni GitHub connector/Actions; Codex tylko gdy potrzebny. Bez TinyFish, dodatkowych Skills/MCP/hooks/config oraz importu gpt-instruct. Nie edytuj globalnego model_instructions_file. Model i effort dobieraj do ryzyka, nie zmieniaj w środku pomiaru A/B. Żaden cache ani ponowny czat nie zastępuje rzeczywistego odczytu źródła.
